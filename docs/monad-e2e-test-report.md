## 1. Executive Summary

This document formalizes the comprehensive validation and test report of the end-to-end lifecycle (**Milestone E1**) of the **AstroAm** protocol on **Monad Testnet**, using **MetaMask Connect** (`@metamask/connect-evm`), the official **Circle USDC** token and the immutable one-way payment channel contract **`AstroAmEscrow` v3**.

The test successfully validated all of the functional and security requirements:
1. **Wallet connection and setup:** Smooth connection with MetaMask, network switch to Monad Testnet and import of Circle USDC.
2. **Opening a prepaid channel:** ERC-20 approval (`approve`) and atomic deposit of **5.00 USDC** into the `AstroAmEscrow` v3 contract.
3. **Cryptographic session key:** Client-side generation of an ephemeral private key stored in `localStorage`, whose public signer was registered in the contract at the time of the deposit.
4. **Frictionless mobile data usage:** Simulation of data traffic consuming **250 MB**, with silent issuance and signing of off-chain EIP-712 vouchers by the session key, without requiring any intervention or MetaMask popup for each megabyte consumed.
5. **Channel close and atomic settlement:** On-chain execution of `close()` by the operator's authorized account (*payee*), collecting the amount consumed (**0.625 USDC**) and transferring the unused remainder (**4.375 USDC**) back to the traveler's wallet in a single on-chain transaction.

## 6. Security and Edge Case Verification

1. **Session Key Protection:**
   - The private key generated in the browser has authority only to sign EIP-712 vouchers associated with the specific `escrowId` and strictly bounded by the maximum deposit of 5.00 USDC.
   - If an attacker extracted the session key from `localStorage`, they could only sign consumption for the mission in progress; they could never drain the user's MetaMask wallet or access funds from other missions.
2. **Timeout Refund Guarantee (`refund`):**
   - In the hypothetical case of a total backend failure or the operator's refusal to execute `close()`, the contract has the `refund(escrowId)` function enabled once the security timeout (30 days) expires. The traveler can autonomously claim 100% of the unclaimed funds without intermediaries.
3. **Preventive Cancellation of Orphan Missions:**
   - The `POST /api/missions/:id/cancel` endpoint was tested on missions with a deposit made but without eSIM provisioning or consumption. The operator calls `close(escrowId, 0, "0x", 0)`, returning **100% (5.00 USDC)** to the traveler without penalty or delay.
